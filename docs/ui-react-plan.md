# UI на React

Серверные экраны «Спринт», «Период» и «Настройка» уже читают слепок. Этот план переносит ту же картинку в React и не меняет формулы. Число на экране берётся из JSON. Браузер не вызывает `compute` и не импортирует `dashboard.metrics`.

Стек: React 19 и Vite 6 на JavaScript. TypeScript не подключаем. Отдельный набор компонентов вроде Tremor не становится источником чисел: линия графика строится по точкам слепка.

Выбрана сетка варианта 5. Темы две: светлая и тёмная. Латунь (`--brass`) помечает, куда смотреть, и не значит «плохо». Переключатель в боковом меню. Выбор запоминается в `localStorage` под ключом `dashboard-theme`. Первый заход без записи берёт тему системы.

Серверный HTML в `web/` и `src/dashboard/api/page.py` живёт, пока React не показывает те же блоки. Стили — один файл токенов, две темы.

## Что остаётся как есть

- `GET /api/sprint`, `GET /api/team`, `GET /api/metrics/{id}`, `POST /api/edits`, `GET` и `POST /api/setup`.
- `null` рисуется как «—», не как ноль. Скрытый блок не оставляет пустую шкалу и подпись «0 SP».
- Нет `riskScore`, карточки утилизации, цветовых порогов 50/80 и вердикта «план достижим».
- Выделение только у того, на что смотреть: добавление и снятие состава, пауза, отмена, блокер, пустая оценка, остаток выше идеала, часы «из прошлого».
- Кнопки сборки нет. Секрет на экран не выходит: в мастере видно имя `authEnv`, не значение токена.
- Ключ задачи — ссылка `{jiraBaseUrl}/browse/{key}`, только если база начинается с `http://` или `https://`.

## Общие куски, их кладём в шаге 2

Дальше все карточки берут одно и то же форматирование. Файлы появляются в шаге 2 и больше не дублируют правила.

- `frontend/src/format.js` — `num`: `null` и `boolean` дают «—», целое число как есть, дробь без лишних нулей. `duration`: секунды слепка в «N ч M мин (S с)», как `_duration` в `page.py`. `ratio`: два знака, если дробь не целая.
- `frontend/src/labels.js` — подписи ролей, состава и причин. Тексты те же, что `ROLE_LABELS`, `SCOPE_LABELS`, `REASON_LABELS` в `src/dashboard/api/page.py`. Неизвестная причина остаётся своим кодом.
- `frontend/src/links.js` — адрес задачи в Jira. Пустой ключ или база без `http` — текст без ссылки.
- Карточка помечается `data-widget` и `data-metric` теми же именами, что серверный HTML. Так проверка ищет блок, а не угадывает вёрстку.
- Подсказка «Как читать» — элемент `details`. Текст подсказки копируется из серверного экрана, формула в подсказке не пересказывается заново.
- Выделение: атрибут `data-attention="true"`. Цвет текста — `var(--brass)` в обеих темах. Красного и зелёного порога нет.

Метрика спринта ищется в `sprint.metrics` по `id`. Нет объекта — блок этой метрики не рисуется, нули на его место не ставятся.

## Шаг 0. Каркас — сделан

`frontend/`: Vite, React, прокси `/api` на `http://127.0.0.1:8765`. Страница читает `GET /api/sprint` и показывает `sprint.id` из ответа. Ошибка ответа остаётся текстом сервера, пустой слепок не подставляется.

## Шаг 1. Оболочка — сделана

Боковое меню: «Спринт», «Период», «Настройка». Шапка: идентификатор спринта и даты `start` — `end`. Плашка покрытия, когда `coverage.timing` равен `none` или `partial`, либо `coverage.membership` равен `incomplete`. Текст плашки называет поле. Переключатель «Светлая» / «Тёмная».

Проверка уже есть: `tests/test_ui_theme.py`.

## Шаг 2. Состав, поток, цикл и ожидание

Экран «Спринт» ниже шапки. Файлы: `frontend/src/SprintScreen.jsx`, `frontend/src/widgets/Scope.jsx`, `Flow.jsx`, `Timing.jsx`, плюс `format.js`, `labels.js`, `links.js`.

### Состав

Блок `data-widget="scope"`. Три карточки из `scopeChange.detail`:

| Поле | Подпись | Выделение |
| --- | --- | --- |
| `committed` | На старте | нет |
| `added` | Добавлены | если число больше нуля |
| `removed` | Сняты | если число больше нуля |

Рядом строка завершения. Текст «N из M» берётся из `completionVsCommitted.detail.done` и `detail.committed`. Долю в браузере не делят. Если метрики нет, `value` равен `null`, не хватает `done` или `committed`, либо `coverage.membership` равен `incomplete` — карточки состава показывают «—», а строка говорит «Завершение к старту: состав на старте не собран». Фразы «всего минус старт» нет.

### Поток

Блок `data-widget="flow"`. Семь счётчиков `sprintFlow.detail.byRole` в порядке `active`, `wait`, `hold`, `queue`, `done`, `canceled`, `total`. Подписи: «В работе», «Ожидание», «Пауза», «Очередь», «Сделано», «Отменено», «Всего». Пауза и отмена выделены, когда счётчик больше нуля. Кольца статусов нет.

### Цикл и ожидание

Один блок `data-widget="timing"`, две карточки `data-metric="cycleTime"` и `data-metric="waitTime"`. Крупное число — `value` в рабочих днях, как лежит в слепке. Подпись — поле `explain`. Раскрытие «Что вошло в число»:

- строка `detail.perIssue`: ключ, `seconds` в подписи длительности, слова «в работе» или «в ожидании»;
- ключ из `population`, которого нет в `perIssue`: «есть в составе медианы»;
- `excluded`: ключ и причина из словаря, строка выделена.

Пустой список входа — фраза «в сумму никто не вошёл». В тексте карточки нет `nominalSeconds` и `workSeconds`.

Проверка: `tests/test_ui_sprint.py` рендерит экран из слепка фикстур и сверяет видимый текст. Случаи: `scope-days` (committed, added, removed, отмена, «1 из 2»), `cycle-reopen` (в цикле секунды `14400`, код `900` один раз), неполный `membership` (прочерк и «состав на старте не собран»). Рендер — `react-dom/server` из собранного модуля, без браузера и без сети. Исходники `frontend/src` не содержат `compute`, `riskScore`, `utilization`.

## Шаг 3. Качество данных, блокеры, команда, таблица задач

Файлы: `frontend/src/widgets/Hygiene.jsx`, `Blockers.jsx`, `People.jsx`, `Issues.jsx`.

### Качество данных

Блок `data-widget="hygiene"` есть, только если метрика `hygiene` есть в слепке. Число — `value`. Список — `detail.items`: ключ и причина. Пустой список — «Плашек нет». Над списком фраза «Это не оценка команды». Просроченный срок в этот список не переносится: он живёт в блокерах.

### Блокеры

Блок `data-widget="blockers"`, если метрика есть. Список `detail.items` в порядке слепка, нумерованный. У строки `data-reason` — первая причина. Подпись — все причины через запятую. Ключ — ссылка в Jira. Балла и слова risk нет. Пустой список — «Список пуст». Число больше нуля выделяется.

### Команда

Блок `data-widget="people"`, заголовок «Команда». Все строки `personLoad.detail.rows`, включая человека с пустым `openKeys`. У него подпись «нет открытых».

Если в строке есть `total`, карточка показывает счётчики `total`, `backlog`, `inProgress`, `paused`, `testing`, `done`, `canceled`, затем `storyPoints` и `openStoryPoints`. Пауза и отмена выделены, когда число больше нуля. `pointsMissing` больше нуля — отдельная строка «Без оценки», выделена. Полоска `.mix` повторяет те же счётчики шириной `count / total`, это не новая формула. Список `issues`: ключ, название, статус, SP если поле не `null`. Роль `hold` в списке выделена. Фамилия — первое слово `name`, остальное и `personId` — подзаголовок.

### Таблица задач

Блок `data-widget="issues"`. Колонки: ключ, название, статус, исполнитель, состав, блокеры, срок. Story points — колонка `data-column="storyPoints"`, ячейка из `storyPoints`. Колонка скрыта целиком, когда `coverage.storyPoints` равен `off`. `null` в ячейке — «—» и выделение, не ноль. Срок — `dueDate`; если `closedBeforeDue` истинно, к дате дописывается «раньше срока». Ячейка срока выделена, когда среди `blockerReasons` есть `overdue`. Ячейка блокеров выделена, когда причины непусты.

Проверка тем же `tests/test_ui_sprint.py`: человек `idle` остаётся, блокеры сохраняют порядок слепка (`overdue` раньше `hold`, если так лежит в файле), `no-points` прячет колонку SP и не печатает «0 SP», ссылка `https://jira.example.com/browse/...` есть только при базе из слепка.

## Шаг 4. Сгорание и тренд

Файлы: `frontend/src/widgets/Burndown.jsx`, `Trend.jsx`. Оба графика — свой SVG. Библиотеку графиков не ставим.

### Сгорание

Блок `data-widget="burndown"` рисуется только когда `coverage.storyPoints` равен `full`, метрика `burndown` есть и `value` не `null`. Иначе блока нет.

Линии — точки `detail.points` как есть: дата, `ideal`, `actual`. Пунктир — идеал, сплошная — факт. Ось X — рабочие дни, которые уже лежат в массиве. День, которого нет в массиве, не дорисовывается. Подпись осей: «Y — количество SP. X — рабочие дни спринта». Рядом «Остаток» и `value`. Остаток выделен, когда у последней точки `actual` больше `ideal`. Под графиком таблица тех же точек: рабочий день, идеал, факт. Меньше двух точек — таблицы достаточно, пустой SVG не рисуется.

Координаты линии считаются только для раскладки уже лежащих чисел: максимум среди `ideal` и `actual`, индекс точки по массиву. Новая сумма SP в браузере не появляется.

### Тренд

Блок `data-widget="trend"` всегда на экране спринта. Бейдж `data-widget="previous"` — только если `sprint.trend.previous` не пуст. В бейдже `sprintId`, `snapshotId` и счётчики `byRole` в том же порядке ролей, что у потока. Нет прошлого слепка — бейджа нет, нули прошлого потока не рисуются.

Спарклайн — элементы `trend.sparkline`: дата и `done`. День, которого нет в массиве, на оси не появляется. Рядом короткий список тех же точек, чтобы число было в тексте, не только в картинке.

Проверка: `points-moved` показывает даты `detail.points` и остаток, равный `burndown.value`. `no-points` не содержит `data-widget="burndown"`. `scope-days` со `history/` содержит в тренде даты, которые есть в `sparkline`, и не содержит пропущенный день между ними. Бейдж прошлого спринта есть только вместе с `trend.previous`.

## Шаг 5. Экран «Период»

Источник — `GET /api/team`. Файл `frontend/src/PeriodScreen.jsx` и виджеты в `frontend/src/period/`: `Hours.jsx`, `People.jsx`, `Epics.jsx`. Загрузка рядом с загрузкой спринта в `api.js` (`loadTeam`). Ошибка ответа — текст сервера, пустой период не подставляется.

Шапка: `period.id`, `period.start` — `period.end`, команда `teamId`. Плашка покрытия — те же поля, что на спринте.

### Не разобрано

Плашка `data-widget="unknown"` стоит над часами, когда у `classification` есть предупреждение `unknown-above-threshold`, либо `value` больше `params.unknownWarnPct`. Текст называет процент и порог. Это покрытие классификации, не оценка команды. Иначе плашки нет.

### Часы в статусе

Блок `data-widget="hours"`. Подзаголовок: «Часы в статусе, не списание». Ряд скрыт, когда `coverage.timing` равен `none`, либо `statusHours.value` равен `null` и `detail.days` пуст. В этом случае одна фраза «Ряд скрыт» и поле покрытия. Кольцо и подпись «0» не рисуются.

Иначе кольцо SVG делит `detail.inheritedSeconds` и `detail.ownSeconds`. Доли кольца — эти два числа, третьей категории нет. «Пришли из прошлого» выделены, когда секунды больше нуля. «Начаты в этом периоде» без выделения. `parallelism` и доля к ёмкости (`value`) — диагностика, два знака, без цвета нормы. Раскрытие перечисляет `detail.days`: человек, дата, `rawSeconds`, `scaledSeconds`. Строка с `outside` помечена «вне состава» и выделена.

### Люди периода

Заголовок «Люди». Это не карточка загрузки спринта. Группы строятся по `classification.detail.paths` и `issues` периода: исполнитель из задачи, путь из слепка. Подпись пути: голова и категория, правило, метка или «нет головы». «Нет головы» и категория `unknown` выделены. Дерево на экране заново не обходится. Порядок людей — порядок `people.detail.rows`, затем те, кого в составе нет. Пустой исполнитель — заголовок «Без исполнителя».

### Эпики

Блок `data-widget="epics"`. Предупреждения `projectList.warnings` — плашка, не пустая таблица:

- `no-epics` — «Список эпиков пуст. Пустая таблица не рисуется.» Таблицы нет.
- `edits-team-mismatch` — пометки не подставлены.
- `unknown-epic:{id}` — чужой эпик назван, запись не скрыта.

Иначе таблица `detail.rows`: ключ, название, статус, feature lead (имя из состава, если оно есть), релиз, заметка. Непустая заметка выделена.

Форма пометки есть, когда `editsEnabled` истинно. Поля: `epicId`, `release`, `text`, `author`. Если `writeTokenRequired`, ещё поле пароля `token`, не cookie. Отправка — `POST /api/edits` телом JSON, тот же набор полей, что принимает сервер. Ответ с ошибкой остаётся списком на экране. Успех перечитывает `GET /api/team`. Форма не меняет число метрики в браузере.

### Завершение

Блок `data-widget="completion"`. Дробь «N из M» из `completion.detail`, если `value` не `null`, состав полный и detail непуст. Иначе «—». Ссылка ведёт на экран спринта. Число здесь не пересчитывается.

Проверка: `tests/test_ui_period.py` на тех же случаях, что `tests/test_period_page.py`. Плашка unknown выше блока часов. Кольцо использует секунды слепка. Нет таймингов — кольца нет. Пустой список эпиков — плашка без таблицы. Неполный membership прячет дробь завершения.

## Шаг 6. Мастер настройки

Источник чтения — `GET /api/setup`. Запись — `POST /api/setup` телом JSON, тот же документ, который сервер пишет в `team.yaml`. Разбор полей формы `apply_form` в браузер не переносим: экран собирает объект документа и отдаёт его целиком. Сервер по-прежнему проверяет схему и секреты.

Файл `frontend/src/SetupScreen.jsx`. Секции те же, что у серверной формы:

- команда: название, PM, тимлид, люди (`id` команды на экране только для чтения);
- календарь: пояс, рабочие дни, окно, перерыв, часы в дне, праздники, дополнительные рабочие дни;
- период: id, начало, конец;
- Jira: режим, поставка, адрес, доска, спринт, имя переменной `authEnv`, поля story points и эпика;
- статусы: `usesDueDate` и строки `statusMap`;
- эпики и связи: приоритет, эпики проекта и техники, типы связей, метки other, правила;
- состав задач: типы, проекты, считать ли сабтаски;
- параметры формул: `minStaySeconds`, `highPriorities`, `maxAgeDays`, `unknownWarnPct`. Версия формулы остаётся 1, поле версии на экране нет.

Шапка называет состояние manifest теми же фразами, что `_state_note`: хеш совпал, разошёлся, файла ещё нет, manifest не подключён. После успешной записи — «team.yaml записан. Слепок и manifest не менялись.» Список `problems` из ответа 4xx показывается над формой, введённые поля не затираются молча.

Токен записи — поле формы, когда сервер требует его для этого bind. Поле не сохраняется в `localStorage`. Значение уходит заголовком, который уже ждёт `serve`, не новым каналом. Секрет Jira в файл не пишется и в ответе мастера не показывается.

Кнопки `build` нет. Экран не вызывает сборку и не обещает новый слепок.

Проверка: `tests/test_ui_setup.py` смотрит исходник формы. В нём есть имена полей серверной формы и нет чтения значения токена Jira. Отдельный тест гоняет `POST /api/setup` уже существующим `tests/test_setup.py`: React-клиент не ослабляет проверку секрета и схему. Этот шаг клиентский тест не поднимает живой сервер наружу.

## Ограничения

Их не снимаем по ходу шагов.

- Виджет не вызывает `compute` и не импортирует движок.
- `null` не заменяется нулём. Скрытый виджет не оставляет нулевую шкалу.
- Нет карточки утилизации, `riskScore`, цветовых порогов и вердикта «план достижим».
- Нет кольца статусов на спринте: те же числа уже в счётчиках потока.
- Нет второго кольца спринта на экране периода.
- Слепок с экрана не переписывается. Правятся только `team.yaml` мастером и файл пометок эпика.
- Секреты на экран не выходят.
- Серверный HTML не удаляется в этих шагах. Его тесты остаются зелёными.

## Как проверять шаг

Автоматические тесты не открывают браузер и не ходят в сеть наружу. Числа ищутся в HTML, который React печатает из уже собранного слепка фикстуры. Ожидаемый HTML не копируют из браузера: строки сверяются с полями `expected.snapshot.json`.

Команда, когда файлы шага уже есть:

```bash
python3 -m pytest tests/test_ui_sprint.py tests/test_ui_period.py tests/test_ui_setup.py tests/test_ui_theme.py tests/test_sprint_page.py tests/test_period_page.py
```

- [x] Шаг 1. Оболочка. Навигация «Спринт», «Период», «Настройка». Шапка и плашка качества данных. Переключатель «Светлая» / «Тёмная».
