## 1. План реализации

Экран — серверный HTML. Браузер не считает медиану, доли и линии. Число на экране берётся из поля слепка. Раскрытие списка — элемент `details`: отдельного JS-сборщика нет, `npm` нет.

Каталоги, которых ещё нет и которые появляются здесь: `src/dashboard/api` (только чтение), `web` (шаблон экрана «Спринт»). `metrics` этот шаг не правит.

### Шаг 0. Документ маршрута

`GET /api/sprint` отдаёт один JSON: `asOf`, `timezone`, `teamId`, `coverage`, `sprint` целиком (метрики, задачи, `trend`). Источник — файл `{out}/{teamId}/{дата}.json`. Функция читает файл и отбирает поля. `compute` не вызывается.

`GET /api/metrics/{id}` для метрик этого экрана отдаёт `version`, `explain`, `params`. Полей `value`, `population`, `excluded`, `detail` в этом ответе нет.

Нет файла, битый JSON или документ не проходит `snapshot.schema.json` — ответ 404 или 422, пустой слепок не подставляется.

Проверка: `tests/test_sprint_api.py`. Отчёт: `docs/m2-reports/00-route.md`.

### Шаг 1. Шапка и плашка покрытия

Страница `/` показывает имя не из кода, а из слепка: спринт, даты, `asOf` как в файле. Часовой пояс рядом, без пересчёта «сегодня» на машине, где открыт браузер.

Плашка покрытия видна, когда `coverage.timing` равен `none` или `partial`, либо `coverage.membership` равен `incomplete`. Текст плашки называет поле, не оценку команды.

Проверка: `tests/test_sprint_page.py`. Отчёт: `docs/m2-reports/01-header.md`.

### Шаг 2. Состав, поток, цикл

Три блока:

- Состав: `committed`, `added`, `removed` из `scopeChange.detail`. Рядом завершение к старту: подпись «N из M» из `completionVsCommitted.detail`, не новое деление. При `value = null` или `membership = incomplete` числа пустые, фраза «всего минус старт» не появляется.
- Поток: семь счётчиков `sprintFlow.detail.byRole`. Кольца статусов нет.
- Цикл и ожидание в одной карточке. Подпись — `explain` из слепка. Раскрытие показывает `population` и `excluded` с причиной.

Проверка: `tests/test_sprint_page.py`. Отчёт: `docs/m2-reports/02-flow.md`.

### Шаг 3. Блокеры, люди, таблица

- Блокеры — список из `blockers.detail` в порядке слепка. Балла и слова risk нет.
- Люди — все строки `personLoad.detail.rows`, включая пустой `openKeys`.
- Таблица задач: ключ, название, статус, исполнитель, scope, причины блокера. Story points — ячейка из поля; `null` остаётся пустой, не нулём. Колонка скрыта целиком, когда `coverage.storyPoints = off`. Due показывается как дата из слепка; пустая дата — пустая ячейка.

Проверка: `tests/test_sprint_page.py`. Отчёт: `docs/m2-reports/03-lists.md`.

### Шаг 4. Burndown

Блок есть только если `coverage.storyPoints = full` и `burndown.value` не `null`. Линия — точки `detail.points` как есть: дата, `ideal`, `actual`. Иначе блока нет и подписи «0 SP» нет.

Проверка: `tests/test_sprint_page.py` на `fixtures/m1/points-moved` и `fixtures/m1/no-points`. Отчёт: `docs/m2-reports/04-burndown.md`.

### Шаг 5. Тренд

Бейдж прошлого спринта — `trend.previous`, если он не `null`. Нет слепка — бейджа нет, нули прошлого потока не рисуются. Спарклайн — только элементы `trend.sparkline`. День, которого нет в массиве, на оси не появляется.

Проверка: страница на снимке `fixtures/m1/scope-days` после `build` с его `history/`. Отчёт: `docs/m2-reports/05-trend.md`.

### Шаг 6. Локальный serve

Команда из раздела 5. Слушает только `127.0.0.1`. Другой адрес процесс не занимает: токена на запись в M2 нет, а не-локальный bind без токена контракт запрещает. `PUT` нет. Кнопки сборки нет.

Проверка: `tests/test_serve.py`. Отчёт: `docs/m2-reports/06-serve.md`.

## 2. Ограничения и допущения

Ограничения, их не снимаем в этом шаге.

- Виджет не вызывает `compute` и не импортирует `dashboard.metrics`.
- `null` не заменяется нулём. Скрытый виджет не оставляет нулевую шкалу.
- Нет карточки утилизации, `riskScore`, цветовых порогов 50/80 и вердикта «план достижим».
- Нет кольца статусов: те же числа уже в счётчиках потока.
- Нет экрана «Период»: часы в статусе, классификация, список эпиков, `PUT /api/edits`.
- Нет `collect`, Docker, живой Jira, Confluence, мессенджера, GitLab.
- Слепок write-once. Serve его не переписывает.
- Секреты на экран не выходят. `authEnv` остаётся именем переменной в yaml, страница yaml не читает.

Допущения, чтобы экран можно было открыть до M4.

- Чтение слепка входит в M2, хотя полный API в схеме модулей стоит на M3–M4. Здесь только `GET /api/sprint`, `GET /api/metrics/{id}` и HTML страницы. `GET /api/team` и `PUT /api/edits` остаются следующим шагам.
- Завершение к старту стоит на карточке состава, рядом с added и removed, как в каталоге. В плане продукта та же цифра названа на экране периода. На период она переедет ссылкой на уже показанное число, второй раз её не считают.
- Страница серверная, без `npm`. Так тест читает HTML и проверяет, что число пришло из слепка.
- Колонка due берёт `dueDate` слепка. Флаг `usesDueDate` в снимок M1 не записан; его эффект уже внутри гигиены и блокеров. Новое поле схемы ради колонки не добавляем.
- История исполнителя по-прежнему не приходит. Экран показывает assignee из строки задачи и не рисует «смену владельца».
- Serve выбирает файл по имени даты. Без `--date` берётся самая поздняя дата каталога команды.

## 4. Ревью блока

После зелёного шага 6 заново открыть шаблон и `src/dashboard/api` против каталога и этого файла. Итог: `docs/m2-reports/review.md`. Найденная ошибка чинится, затронутые тесты гоняются снова.

Список проверки.

- На экране нет числа, которого нет в слепке этого запроса.
- `null` не стал нулём: burndown, завершение, тренд прошлого спринта.
- Состав при неполном membership пустой, а не «текущие минус старт».
- Отменённые видны в счётчике `canceled` и не названы сделанными.
- Раскрытие KPI — это `population` и `excluded`, не пересчитанный список.
- В исходниках `web/` и `api/` нет импорта `dashboard.metrics` и нет слов утилизации и risk.
- Serve не пишет в каталог слепков и не слушает внешний адрес.
- Кнопки «пересчитать» нет.

## 5. Локальный хост для ручной проверки

Это проверка глазами на своей машине. Агент её не заменяет: он не открывает браузер на чужом компьютере.

Сначала снимок из уже лежащей фикстуры. Движок M1 для этого достаточен, экран появится после шага 6.

```bash
python3 -m dashboard.orchestrator.build \
  --team fixtures/m1/scope-days/team.yaml \
  --bundle fixtures/m1/scope-days/canonical.json \
  --out var/snapshots
python3 -m dashboard.api.serve \
  --snapshots var/snapshots \
  --team card \
  --host 127.0.0.1 \
  --port 8765
```

В браузере: `http://127.0.0.1:8765/`.

Чтобы увидеть скрытый burndown, второй каталог и второй запуск на другом порту:

```bash
python3 -m dashboard.orchestrator.build \
  --team fixtures/m1/no-points/team.yaml \
  --bundle fixtures/m1/no-points/canonical.json \
  --out var/snapshots-no-points
python3 -m dashboard.api.serve \
  --snapshots var/snapshots-no-points \
  --team card \
  --host 127.0.0.1 \
  --port 8766
```

Для `scope-days` бейдж прошлого спринта появляется, только если перед `build` в `{out}/card/` уже лежат файлы из `fixtures/m1/scope-days/history/`. Иначе бейджа нет — это правильное пустое состояние, не ошибка экрана.

Что смотреть руками.

- Счётчики состава и потока читаются без кольца и без цветной шкалы.
- Раскрытие цикла показывает ключи и причины, страница не перезагружает числа.
- В режиме без SP блока burndown нет.
- Обновить страницу можно. Кнопки, которая запускает `build`, нет.
- Адрес с другой машины на этот порт не открывается: слушает только localhost.
