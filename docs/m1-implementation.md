Рабочий порядок для движка. Формулы и границы модулей — в [m1-plan.md](m1-plan.md). Этот файл говорит, в каком порядке писать код, чем закрывать шаг и куда класть отчёт.

Каждый шаг заканчивается зелёными тестами этого шага и отчётом в `docs/m1-reports/`. Следующий шаг не начинается на красных тестах предыдущего. После шага 7 — отдельный проход ревью по каждому блоку, не по памяти реализации.

Команды, когда файлы уже есть:

```bash
python3 scripts/check_contracts.py
python3 -m pytest
```

## Шаг 0. Схема снимка

Кода движка нет. В схему снимка добавляются поля, без которых формулам некуда положить факт: `dueDate` и `closedBeforeDue` у задачи, `detail` и `explain` у метрики, `trend` у спринта, `bundle` в `inputHashes`. В календарь — необязательный `breakStart`. В каталог — две уточняющие фразы: где лежит перерыв и когда ключ попадает в `excluded` из-за короткого пребывания. Версии формул не меняются.

Проверка: `python3 scripts/check_contracts.py` и `tests/test_schema.py`. Отчёт: `docs/m1-reports/00-schema.md`.

## Шаг 1. Конфиг и время

`pyproject.toml`, `src/dashboard/config`, `src/dashboard/metrics/time.py`. Загрузка YAML по схеме, отказ при плохом окне дня и чужой версии каталога или формулы, хеши правил. `work_seconds` — единственная арифметика: праздник, extra workday, перерыв по `breakStart` и по центру окна, полночь UTC не равна полуночи команды.

Проверка: `tests/test_config.py`, `tests/test_time.py`. Отчёт: `docs/m1-reports/01-config-time.md`.

## Шаг 2. Цикл и срок

`cycleTime` и `waitTime`: сумма роли, не спан. Короткий заход, очередь между заходами, выход из terminal. Дата закрытия в зоне команды: строго раньше due или нет.

Проверка: `tests/test_cycle.py`. Отчёт: `docs/m1-reports/02-cycle.md`.

## Шаг 3. Состав спринта

`sprintFlow`, `scopeChange`, `completionVsCommitted`. Add на день 3, remove на день 7, отмена в знаменателе.

Проверка: `tests/test_flow.py`. Отчёт: `docs/m1-reports/03-flow.md`.

## Шаг 4. Классификация

Ромб, цикл связей, метка поверх головы, задача без головы → `unknown`, ребро `Blocks` не иерархия.

Проверка: `tests/test_classify.py`. Отчёт: `docs/m1-reports/04-classify.md`.

## Шаг 5. Часы в статусе

Два тикета, масштаб дня целыми секундами, inherited и own в одном дне. Ноль прошедших рабочих дней → темп `null`. Слова utilization в полях нет.

Проверка: `tests/test_hours.py`. Отчёт: `docs/m1-reports/05-hours.md`.

## Шаг 6. Остальные карточки

Гигиена (одна причина), список блокеров, люди с нулями, burndown от `storyPointsAtAdd`, список эпиков, покрытие.

Проверка: `tests/test_cards.py`. Отчёт: `docs/m1-reports/06-cards.md`.

## Шаг 7. Сборка

`edits`, `snapshotstore`, `orchestrator.build`. Слепок write-once, правки не переписываются, чужой хеш правил останавливает build. Золотые пары в `fixtures/m1/` написаны по каталогу. Текст «Как считается» содержит параметр фикстуры.

Проверка: `tests/test_build.py`, `tests/test_gold.py`. Отчёт: `docs/m1-reports/07-build.md`.

## Ревью

После зелёного шага 7 заново прочитать каждый модуль против каталога и тестов. Итог: `docs/m1-reports/review.md`. Найденная ошибка чинится и соответствующие тесты прогоняются снова.
