# Приёмка установки

Установка принята, когда выполнены все пункты. Валидный YAML сам по себе приёмкой не является.

- `python3 scripts/check_contracts.py` проходит на контракте репозитория, и YAML этой команды проходит ту же схему и те же инварианты.
- Для выбранного спринта число задач `done` на доске и в снимке совпало после фильтра `scope` (типы, проекты, сабтаски).
- Исполнители сопоставились не ниже 98% задач состава. Для Cloud это `jiraAccountId`, для Server — `jiraUsername`.
- `coverage.membership = complete`. Иначе committed / added / removed пустые, и экран это показывает.
- `unknownPct` не выше порога, либо плашка покрытия стоит над часами и разбор её учитывает.
- 15 задач, размеченных вручную, сошлись с путём классификации в снимке.
- Хеш правил в manifest записан. Повторный `build` на тех же raw не меняет байты предыдущего слепка.
- `edits.json` после `build` тот же.
- На экране нет карточки утилизации, цветного процента точности и балла риска.
- Due включён только при `workflow.usesDueDate: true`. Дата закрытия сравнена в `calendar.timezone`.

Кто правит файл после приёмки:

- PO — эпики и связи, не в день разбора, а до него;
- PM — карта статусов, флаг due, состав типов;
- тимлид — окна людей, отсутствия, `allocation`.

Смена этих разделов требует нового принятия хеша, не тихого пересчёта.
