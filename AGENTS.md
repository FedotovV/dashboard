# Agent instructions

### Overview & Scope

Репозиторий — контракт универсального командного дашборда для PM и PO, затем реализация по вехам M0–M5. Этот файл действует на весь репозиторий. Вложенных `AGENTS.md` нет; ближайший к файлу побеждает.

Источник правды: `docs/plan.md`, `docs/metric-catalog.md`, схемы в `schema/`. README на них только ссылается.

### Agent Role

Агент реализует текущую веху из плана и не расширяет продукт.

Можно: править контракт вместе с примером и `scripts/check_contracts.py`; начинать код модуля, когда предыдущая веха по плану закрыта.

Нельзя: возвращать в v1 метрики из раздела «Не входит в v1»; называть часы в статусе утилизацией; добавлять `riskScore` и цветовые пороги; вводить версию формулы без человека; писать секреты в YAML; переносить хосты и имена из внутреннего референса.

### Build, Test & Validation Commands

Проверка контракта и движка:

```bash
python3 scripts/check_contracts.py
python3 -m pytest
```

`pytest` не вызывать, пока в репозитории нет `pyproject.toml`. Docker и `npm` не вызывать: каталогов `web` и compose в M1 нет.

Даты в YAML держать в кавычках.

### Conventions & Patterns

- Документы и подписи продукта — на русском. Английский — у имён систем, полей API, статусов Jira as-is и id метрик.
- Формула живёт в каталоге. Виджет рисует снимок и сам не считает.
- Цикл v1 — сумма интервалов роли `active`, не спан референса.
- Неразобранная задача — `unknown`. Ребро таксономии — только parent→child.
- Слепок write-once. Правки PM не содержат чисел метрик.
- Пути модулей — таблица в `docs/plan.md` и схема в `docs/architecture.html`. Не создавать каталоги модуля до его вехи. Текущий шаг — M1, порядок срезов в `docs/m1-plan.md`: каталог модуля появляется в том срезе, где у него появляется код.
- Искать по `docs/`, `schema/`, `scripts/`. Игнорировать `.git/`.

### Dos and Don’ts

- Меняя схему, обновить пример и прогнать `scripts/check_contracts.py` в том же изменении.
- Не дублировать план в README.
- Не ставить Confluence, мессенджер и GitLab на критический путь v1.

### Safety & Guardrails

- Секреты только через `authEnv`.
- Не ходить в чужие Jira, Confluence, GitLab и мессенджеры и не коммитить выгрузки с персональными данными.
- `serve`, когда появится, слушает localhost, пока нет токена на запись правок.

### Git & PR Rules

- Базовая ветка: `Flutter`.
- Коммит говорит, что изменилось и зачем.
- В PR указать затронутые контракты и что `python3 scripts/check_contracts.py` прошёл.

### Additional rules

- Спорные продуктовые решения лежат в `docs/plan.md`, раздел «Ревью и что из него взято».
- Команды дописывать сюда, когда они появляются в репозитории.
